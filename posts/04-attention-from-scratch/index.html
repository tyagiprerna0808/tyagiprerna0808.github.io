Part 4 of Building Blocks of Modern AI. We’ve turned text into tokens; now we give the tokens a way to talk to each other.

The word that needs context

Here’s a sentence: “The river bank was muddy.” And here’s another: “She deposited the cheque at the bank.”

Same four letters, bank. Two completely different things. You told them apart without noticing, using the words around each one. That’s the whole problem of language in miniature: meaning isn’t in the word, it’s in the company the word keeps.

For years, models were bad at this. RNNs read strictly left to right, squeezing everything seen so far into one fixed memory vector, so by the end of a long sentence the beginning had mostly evaporated.

Attention is the idea that threw that out. It’s so central that the paper introducing the transformer just called it all you need. The move looks obvious in hindsight: instead of compressing the past into a single vector, let every token look directly at every other token and decide, for itself, which ones matter.

So bank, sitting beside river and muddy, leans toward those two, and quietly becomes a different vector than the bank that sits beside cheque.

That’s the entire intuition. The rest of this post is making it precise.

Q, K, V: a tiny game of question and answer

To let tokens “look at each other,” attention gives every token three jobs, by projecting it three different ways:

  • Query (\(Q\)): what am I looking for?
  • Key (\(K\)): what do I have to offer?
  • Value (\(V\)): and if you pick me, here’s what you actually get.

Picture a room full of people. Each token holds up a query (“I’m the word bank, I’m confused, anyone got context?”), compares it against everyone else’s key (“I’m river, I’m relevant to you”), and the better two match, the more of that neighbour’s value it carries home.

“How well do a query and a key match?” is just their dot product. Compute it for every pair, squash the scores into weights that sum to 1 (softmax), and use those weights to mix the values. Written out, the whole mechanism is one line:

\[\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{QK^T}{\sqrt{d_k}}\right)V\]

Don’t let the symbols hide what it is: a weighted average of values, weighted by how much each query matches each key. That’s attention, top to bottom.

The one detail everyone glosses over: √dₖ

There’s a small divisor in that formula, \(\sqrt{d_k}\), that’s easy to wave off as bookkeeping. It isn’t. Drop it, and training quietly falls apart.

Here’s why. If queries and keys are roughly random with variance 1, their dot product has variance \(d_k\), so in a model with a large head dimension the raw scores swing to big positive and negative numbers. Feed those into softmax and it saturates: one weight goes to ~1, the rest to ~0, and the gradient flatlines. The layer stops learning.

Dividing by \(\sqrt{d_k}\) pulls the scores back to variance 1, keeps softmax in its sensitive range, and the gradients keep flowing. One square root, standing between you and a model that refuses to train.

Attention, in fourteen lines

None of this is hand-wavy. It’s short enough to write from scratch:

import numpy as np

def scaled_dot_product_attention(q, k, v, mask=None):
    d_k = q.shape[-1]
    # 1. Scores: how much each query matches each key
    scores = np.matmul(q, k.transpose(-2, -1)) / np.sqrt(d_k)

    # 2. Causal mask: forbid looking at future tokens
    if mask is not None:
        scores += (mask * -1e9)

    # 3. Softmax: turn scores into weights that sum to 1
    weights = np.exp(scores) / np.sum(np.exp(scores), axis=-1, keepdims=True)

    # 4. Mix the values by those weights
    return np.matmul(weights, v), weights

That is the heart of every transformer you’ve ever used. Everything after this is making it faster and cheaper, because the basic version has two expensive habits.

The bill comes due: the memory wall

The first habit shows up when a model generates text one token at a time. To produce token \(L+1\), it has to attend to all \(L\) tokens before it, and recomputing the keys and values for that entire history, every single step, is pure waste.

So we cache them. The KV cache stores each token’s \(K\) and \(V\) once and reuses them forever after. Brilliant, except the cache grows with every token and every concurrent request, and it grows fast: for a 70-billion-parameter model with a 128K context, it can swell to tens of gigabytes of fast GPU memory. For most people serving LLMs, this cache, not the math, is what runs out first.

That pressure is exactly why modern models bother with Grouped-Query Attention: instead of every query head carrying its own private key/value, several query heads share one set. Llama 3 does this. You lose almost no quality and you shrink the cache dramatically, a direct answer to the memory wall.

Why your GPU was sitting idle: Flash Attention

The second expensive habit is the \(QK^T\) matrix itself. For a sequence of length \(L\) it’s \(L \times L\), quadratic, and the surprise is where the cost actually lives. It’s not the multiplications. It’s shuttling that giant matrix back and forth between the GPU’s big-but-slow memory and its tiny-but-fast on-chip memory.

Flash Attention fixes it without changing a single number in the result. It tiles the computation: it breaks the huge matrix into blocks small enough to live in fast memory, finishes each block there, and never writes the full thing out. Same math, up to ~3× faster, purely by respecting where the data physically sits. (We’ll meet this memory-versus-compute story again and again.)
